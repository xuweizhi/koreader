# Anx 风格 KOReader：验收与回归矩阵

适用对象：[实施方案](implementation-plan.zh-CN.md)、[执行批次](tasks.zh-CN.md)和 [AI 执行入口](ai-execution.zh-CN.md)。修订：v2。状态：测试设计，尚未执行；实际结果记录在[执行状态](execution-state.json)及它引用的证据文件中。

## 1. 如何认定“保留 KOReader 大部分功能”

先在同一核心版本、相同设备和相同数据副本上运行经典界面基线，再开启新 UI 比较。

- 对选定设备原本可用的关键阅读与数据流程，要求全部通过。
- 内置插件按下方清单逐项记录；不支持的硬件能力标注 N/A 和原因，不能以“UI 没有入口”作为 N/A。
- 视觉保留和功能保留分别记录：高级窗口保留原外观仍可算功能保留，但不能算 UI 已统一。
- 第三方仅按完整版本和实际组合声明兼容，不外推到全部插件或后续版本。
- 状态只能为：未测、通过、失败、原版已有失败、N/A。后两项必须附证据和理由。

## 2. 测试环境与书籍样本

### 2.1 环境

| 环境 | 最低覆盖 | 必须记录 |
| --- | --- | --- |
| Android 彩屏 | 竖屏、横屏、触摸、系统返回、屏幕键盘、前后台切换 | 型号、系统、分辨率、DPI、插件版本 |
| Linux SDL | 窄窗口、宽窗口、键盘、鼠标、窗口尺寸变化 | 发行版、显示缩放、SDL 版本、输入方式 |
| 一台灰度或彩色墨水屏 | 实际阅读、刷新、翻页键、睡眠唤醒、灯光 | 型号、固件、刷新设置、彩色/灰度模式 |

未取得实机的环境保留“未测”，不能宣布该环境通过，也不能擅自取消已约定的目标。Linux 本地开发继续，Android 首发验证保持待完成；候选交付明确仅覆盖实际验证范围。所有环境使用独立配置目录与测试书籍副本；测试 sidecar 也处于隔离目录。

## 6. 性能与资源预算

下表是 **需要按平台校准的初始预算**，没有任何一项已被测量证明。P0 采集 Linux 原版及原型基线，并在 G0 冻结 Linux 使用的测量边界与预算；未实现功能先保留目标，到 W31 测量。Android/墨水屏预算在对应设备基线建立后确认，不能把 Linux 数据直接套过去。调整必须记录原预算、测量、原因和新预算，不能在发布前静默放宽。

| ID | 指标 | 初始预算/方法 |
| --- | --- | --- |
| Q01 | 启动与书架首屏 | 同设备同缓存状态测经典版和新 UI；冷启动分别记录总时长，热首页首批可交互内容目标 500 ms 内；首次索引单列 |
| Q02 | 阅读和操作响应 | 工具栏关闭时翻页 P95 不超过 max(原版 P95 × 1.10，原版 P95 + 20 ms)；普通本地 UI 动作处理目标 P95 ≤ 150 ms，物理墨水屏刷新单列 |
| Q03 | 内存与缓存 | 封面缓存初始上限：墨水屏 8 MiB、彩屏 24 MiB；额外常驻内存预算分别 16/48 MiB；均指增量，按各平台实际基线校准 |
| Q04 | 长时稳定 | 100 次开书/关书及 100 次工具页开关，无残留实例或监听器；预热并 GC 后对比内存，末段不得持续单调增长；差值目标 ≤ max(2 MiB，预热后占用的 5%) |

采样要求：

- 记录 CPU/内存、设备电源模式、书籍、DPI、插件组合和缓存状态。
- 启动至少 20 次，交互/翻页至少 100 次；保留每次原始值及 P50/P95，不只给平均值。
- 使用同一测量边界；分别记录数据准备、渲染提交和实际显示。
- 网络不纳入基础翻页指标；AI 流式返回按实际插件能力测量，UI 空闲时不持续刷新。
- 压力测试包括滚动期间取消封面/索引，以及退出后迟到的网络响应。

## 7. 故障恢复与升级矩阵

| ID | 注入/操作 | 通过条件 |
| --- | --- | --- |
| F01 | 在新 UI 设置或原插件管理禁用新 UI | 重新进入经典界面，书籍/笔记/统计保持可读 |
| F02 | 插件初始化失败、主文件损坏、恢复标记残留 | 可回退；无法进入时按文档移出插件目录恢复，不触碰阅读数据 |
| F03 | 切书/旋转/关闭时仍有封面、索引或 AI 请求 | 清理和 generation 校验有效；无回调访问已释放实例 |
| F04 | 卡住或 native 崩溃导致普通 Lua 捕获失效 | 外部禁用插件和回退同基线版本两条路径实测成功 |
| F05 | 从旧设置升级，再撤回新 UI | UI 配置迁移可恢复；原版继续读取书籍和 sidecar；缓存可删除重建 |

只切换界面、不进行阅读编辑时，核心数据应无非必要变化。发生正常阅读操作时比较内容、锚点、书单和统计等语义结果；更新时间、访问记录等合理变化不作为误报。

## 8. 自动化和人工验证分工

自动化优先覆盖生命周期、导航、适配器能力缺失、缓存失效、任务取消、书籍切换和设置迁移；复用现有 readerui、readerannotation、readerbookmark、pluginloader、uimanager 等相关测试。

视觉改动以固定字体/DPI/主题的真实应用截图对照为主。AI 可使用实际可用的截图/交互工具检查布局和可操作性；无法观察或操作的项目标未测。触摸手感和残影等需要实机观察。截图对比遮蔽时间、电量、网络状态，不为每个颜色常量编写重复实现的测试。

墨水屏残影、触摸手感、硬件键与休眠恢复必须实机验证。自动化通过不能替代这部分。

实施时运行入口：./kodev check、./kodev test front；局部测试过滤方式应在依赖准备好后按当前 kodev 帮助确认。最终发布阶段运行一次完整前端回归，并保存原版本已存在的失败列表。

## 9. 发布签收

以下清单用于 G5-release。G5-local 只签收 Linux 本地及不依赖外部设备/服务的适用范围，并附待验证清单；两者不能混用。

- [ ] 核心、子模块、新 UI 与第三方插件完整版本已锁定。
- [ ] 所有基线可用的关键阅读/数据场景通过。
- [ ] 内置插件逐项记录，第三方白名单和冲突组合明确。
- [ ] 四类视觉基准和全部空态/错误态已检查。
- [ ] 性能原始数据、测量边界和冻结预算可复核。
- [ ] 至少完成目标 Android/Linux 验证；墨水屏支持声明与实测范围一致。
- [ ] 经典界面切换、外部禁用、版本回退和旧数据恢复均实际演练。
- [ ] 来源/许可文件、打包步骤、使用说明、已知限制完整。
- [ ] 所有数据损失、不可恢复启动失败和基础阅读失败均已解决。

完成标志是“指定版本组合在指定设备和样本上满足上述标准”，而不是“UI 看起来像 Anx”或“已有插件能安装”。

## 10. AI 执行的关卡切片与证据

### 10.1 结果必须限定范围

一条验收记录由 `场景 ID + 阶段 + 平台/后端 + 版本身份 + 子场景范围` 唯一标识。例如，`A04@G0/Linux/原批注窗口往返` 通过，并不使 `A04@G3/Linux/新笔记页编辑导出` 或 `A04@W36/Android` 自动通过。

批次依赖和验收编号不是同一种东西。任务表中的 K00–K08 是执行入口的检查方法；本文件中的 C01–C05 是插件/AI 功能场景，不能混淆。没有执行的命令、测试匹配数为零、mock 服务返回和设计稿均不能作为真实集成通过的证据。

### 10.2 G0 只验证原型闭环

| 场景切片 | G0 必须完成 | 留到后续的范围 |
| --- | --- | --- |
| A01@G0 | S01 中文 EPUB 与 S04 文本 PDF 从新首页打开 | 全格式、重排、漫画、损坏文件的完整矩阵在 G3 |
| A03@G0 | 翻页后关闭、重开、重启并切经典界面，核对真实位置 | 自定义进度/目录面板在 G3 |
| A04/A08@G0 | 经新首页开书，在原窗口创建/编辑批注或书签，关闭并用经典 UI 核对内容与锚点，再反向验证 | 新笔记列表、跨书索引与导出组合在 G3 |

### 10.4 最低证据要求

每条结果包含：批次、场景切片、执行时间、环境、样本校验值、核心与依赖版本、未提交文件快照/校验值、操作或完整命令、退出码/匹配用例数、实际结果、日志/截图路径、未覆盖范围。字段模板见执行入口。

- 视觉：G5-local 至少四类真实应用画面，即竖屏书架、宽屏书架、阅读工具栏、笔记列表；明确字体/DPI/主题，覆盖空态与错误态。目标稿与截图分别保存。
- 数据：保留操作前后的测试副本或可复核语义快照；核对批注内容/锚点、进度、书单、文件归属，不强求合理访问时间戳字节不变。
- 自动化：保存实际命令与测试数；若只测 fake 文档或 mock 插件，说明边界，再补真实集成。
- 故障：隔离注入与恢复必须实际执行。受控结束进程用于验证外部恢复，不代表完整覆盖所有 native 崩溃原因；无法安全复现的类型明确保留限制。
- 性能：保留逐次数据与 P50/P95；不同平台独立比较，不能拿开发机数值替代手机或墨水屏。
- 有效性：后续代码修改使相关结果过期时，保留旧记录并标为 stale；只重验受影响范围，最终候选版本必须有相匹配的证据。

完成状态以实际证据为准；AI 文字描述“应该可用”或“逻辑上通过”不属于通过结果。
