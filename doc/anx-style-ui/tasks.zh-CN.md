# Anx 风格 KOReader：AI 执行批次

修订：v2。以下 40 批均为实施契约，实际状态只维护在 [execution-state.json](execution-state.json)。从 [AI 执行入口](ai-execution.zh-CN.md)开始，遵守[产品边界](implementation-plan.zh-CN.md)与[验收范围](acceptance.zh-CN.md)。

表中 R 为必读源码，S 为可改范围，K 为检查方法，定义见执行入口。每批隐含 S0（状态、证据与必要文档）、必要的 S7（有意义的测试）及 K00（工作区检查）。新增文件按需要创建，不先搭完整空框架。

验收编号必须带本批范围，例如 A04@G0 的原批注窗口往返。所有批次都需保存实际命令、源代码身份和结果；下表的“完成条件”是未来要求，不能当作已执行结果。

## W40：返回 Anx 书架入口增强

根据用户“Anx书架的按钮可以更明显一点吗”的反馈，在经典书架和阅读界面的原主菜单首个分页及工具分页顶部增加加粗、带分隔线的“打开 Anx 书架”。保留原更多工具入口，沿用原菜单关闭、阅读保存和返回路径。重复构建菜单不重复插入，禁用后不贡献可操作入口，用户自定义菜单顺序仍按原规则处理。

完成条件：当前 Anx 回归通过；真实 SDL 的中文标准屏和窄屏分别实际点击四个入口，检查标签、几何、关闭菜单及返回书架；提高 Android 版本码和内层资源版本，用同一开发证书重新打包，逐文件核对插件。新包与旧基线分目录交付，完整旧回归和平台运行结果保留其原始适用版本。实现与结果见[入口更新记录](entry-update.zh-CN.md)。

## 全部批次共用的完成规则

1. 明确实现行为、可改路径和实际接口，不以空页面、静态假数据或 TODO 作为功能交付。
2. 编码完成与验证完成分开；本地、模拟器、实机、真实服务分开。部分场景通过只能登记具体切片。
3. 保存命令、退出码、用例数、日志/截图和源码快照；有 mock 时说明它只验证什么。
4. 任务失败时记录复现、原版是否同样失败、修复和重验；用户数据不得用作故障试验。
5. 更新唯一状态文件后自主继续下一批。只有真正需要外部条件的批次等待，不反复请求确认已确定的设计。
6. 不设置 AI 工期保证；以可运行行为和有效验证衡量进度。完成当前批次不等于完成用户的全部目标。
