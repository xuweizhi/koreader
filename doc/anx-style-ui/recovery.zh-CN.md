# 安装、数据归属与恢复

本插件使用 KOReader 原阅读引擎和原数据模块。先退出 KOReader，再把发行包里的 `anxui.koplugin` 整个目录放到本机 KOReader 的 `plugins` 目录。这里的“本机目录”取决于安装方式，不要把本仓库 `/data/koreader` 路径照抄到 Android。首次从原菜单“更多工具 → Anx 书架”手动进入；启用默认首页在 Anx 外观中单独设置。

书架页头“经典”或关闭按钮返回原文件管理器；阅读器原菜单里“Anx 阅读工具”打开目录、笔记、排版等入口。原菜单、手势和选段操作继续可用。原设置搜索和高级配置也保留。

| 数据 | 保存位置/负责模块 | 移除 Anx UI 后 |
| --- | --- | --- |
| 阅读位置、书签、划线、备注 | 原 DocSettings/ReaderAnnotation；书籍 sidecar 或原用户选定位置 | 原版继续读取 |
| 历史、收藏、书单 | 原 ReadHistory/ReadCollection | 原版继续读取 |
| 导入书架与扫描目录 | 原 `collection.lua` 的专属 Anx 书单及其 `anxui_scan_roots` 设置 | 原版可继续打开该书单；原书和批注保持原位置 |
| 阅读统计 | 原 `statistics.sqlite3` 与统计插件 | Anx 仅查询已保存区间；没有第二个计时器 |
| UI 选项 | 原全局配置 `settings.reader.lua` 中的 `anxui` 命名空间 | 可以保留，原版忽略该命名空间 |
| 初始界面 | 原全局配置 `start_with`；选择 Anx 时为 `anxui` | 插件禁用或移除时原启动流程回到文件浏览器；也可在原初始界面菜单重新选择其他首页 |
| 跨书笔记索引 | 设置目录 `anxui-notes.sqlite3` | 可删除重建；它不是原笔记 |
| 封面与书籍信息 | 复用原 coverbrowser 的缓存 | 继续由原插件管理 |
| AI 配置、凭据、对话 | 可选 KOAssistant 自身管理 | 不复制到 Anx 配置；独立保留/卸载 |

统计页显示已入库的区间。当前尚未结束的页面计时由原统计插件掌管；打开经典统计时原插件可能把已完成区间入库，所以两次不同时间的画面可自然不同。禁止为追赶瞬时数值再加一套计时或写统计数据库。

## 可进入应用时

1. 先从书架右上角菜单的“经典界面”或系统返回键回到经典界面。
2. 在原插件管理器里禁用 Anx UI，然后按原提示重启。
3. 用原书架打开原书，阅读位置与笔记由原模块恢复。

Anx 页面构造中断会留下独立恢复标记，下次保留经典入口，并提示重试。未知 schema 或损坏的 Anx 命名空间不会自动覆盖；用户明确选择重置时只重置该命名空间，不重置 KOReader 全局设置。

## 无法进入应用时

退出或结束 KOReader 进程，在其 `plugins` 目录之外暂存 `anxui.koplugin`，再启动同一固定版本的 KOReader。移出整个插件目录即可，不要删除书籍、sidecar、原设置、历史或统计库。若编辑原 `settings.reader.lua` 禁用，请只在已有 `plugins_disabled` 表增加 `anxui = true`，保留其他键；不要用空配置覆盖整份文件。

本地恢复验证使用同一核心版本与原生库，在独立安装副本中实际执行了强退后的外部禁用、移出插件、损坏主文件和初始化失败，并重开原测试书。证据在 `/data/koreader-anx-work/evidence/W32/faults-02/result.json`。12 个阶段均通过，每次核对原笔记文字/锚点/页码、收藏与原有统计行。故障样本及原始日志保留；没有在真实用户书库中注入故障。

受控 SIGKILL 验证的是“不运行 Lua 关闭回调时仍能外部恢复”，不代表已经复现所有原生引擎崩溃。它只作用于本次隔离测试进程组。初始化与配置恢复也在真实 SDL 进程中执行；不是仅凭 mock 判定。

## 可选 AI

KOAssistant 是独立可选插件，不会随 Anx 入口自动安装或联网。已验证版本和原接口见 [固定版本审计](koassistant-audit.zh-CN.md)。版本不符时 Anx 拒绝桥接；仍可从该插件自己的原入口处理配置/升级。首次进入可能显示 KOAssistant 原配置向导。服务配置存在不表示网络或模型已验证；实际请求、取消、超时与返回保存按 W38 单独验收。

## 已知平台边界

Linux SDL 的模拟灰度、前光/休眠菜单和键鼠验证不能替代墨水屏真机。Android APK 的安装/输入/后台表现由独立平台结果记录。开发测试签名与现有其他签名的 KOReader 不能原地互相覆盖；使用目标设备前应确认包身份与既有数据位置。最新已验证范围和待测项以 [执行记录](execution-state.json) 及最终支持矩阵为准。
